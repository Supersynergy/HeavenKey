# Vom Download zum freigegebenen Auftrag

1. Paket wählen. macOS Apple Silicon oder Intel, Windows x64 oder Linux. Vergleiche den Download mit `SHA256SUMS`. Das GitHub-Repository ist privat: Verwende ein berechtigtes Konto. „Nicht gefunden“ ist kein Tresorfehler.
2. Starten. Auf macOS 14+ `HeavenKey.app` nach Programme ziehen und öffnen. Windows und Linux verwenden den beiliegenden Browser-Starter. Bei einem belegten Port die bestehende Instanz beenden. Die macOS-App übernimmt keine fremde Verbindung.
3. Tresor einrichten oder wiederherstellen. Wähle ein langes Masterpasswort, das du sonst nirgendwo verwendest, und bestätige es. Eine vorhandene verschlüsselte Sicherung stattdessen über „Ich habe schon eine Sicherung“ auswählen. Kein Cloudkonto nötig. Ohne Passwort beziehungsweise eingerichteten kompatiblen Passkey ist keine Entschlüsselung möglich.
4. Einen Login speichern. Titel, Nutzername, Passwort und genaue Website eintragen. Alternativ unter Einstellungen einen CSV-Import prüfen. Neue Einträge, Duplikate und Konflikte vor der Übernahme ansehen. Zuerst mit einem Testkonto üben.
5. Sicherung prüfen. Eine verschlüsselte Sicherung exportieren, getrennt aufbewahren und ihre Wiederherstellung in einem eigenen Testtresor prüfen. Ein Klick auf Export beweist noch keine funktionierende Sicherung.
6. Passkey ergänzen. Unter Einstellungen einen kompatiblen Passkey einrichten. Der lokale Passwortmanager benötigt PRF-Unterstützung des Authenticators. Im macOS-WebView ist Hardware-Kompatibilität gesondert zu prüfen; „Ansicht → Im Browser öffnen“ ermöglicht den Wechsel. Masterpasswort als Rückweg behalten.
7. Browser verbinden. Die Erweiterung ausdrücklich installieren, in HeavenKey einen einmaligen Code erzeugen und in der Erweiterung verwenden. Website und Felder vor Autofill prüfen. Native App und Erweiterung haben getrennte entsperrte UI-Sitzungen.
8. SFTP einrichten. „Erste Schritte → Mit Browser und Agenten arbeiten → SFTP und SSH einrichten“ führt direkt zur passenden Karte. SSH-Schlüssel im Tresor erzeugen, nur den öffentlichen Teil beim Hoster hinterlegen und den Host-Schlüssel unabhängig prüfen. Transferprogramme bekommen durch einen Katalogeintrag keine Zugangsdaten.
9. Agent koppeln und begrenzen. Den geschützten Agentenzugriff in den Einstellungen öffnen. Prüfe den Empfänger und das genaue Ziel. Kontrolliere die erlaubte Aktion sowie Pfad und Laufzeit. Erst eine konkrete Anfrage freigeben. Die Einrichtungshilfe erteilt selbst keine Rechte. Shell-Agenten benötigen zusätzlich den eingeschlossenen Startweg; ein weiterer freier Host-Zugang umgeht diese Vertrauensgrenze.
10. Auftrag beenden. Freigabe widerrufen oder Tresor sperren. Auf macOS beendet das Schließen des letzten App-Fensters auch den eigenen Dienst. Unter Windows/Linux den ausdrücklich gestarteten Dienst beenden. Ein Browserfenster allein beendet diesen Dienst nicht.
11. Aktualisieren. App beziehungsweise Programmdateien ersetzen, den Datenordner erhalten und danach Version und gesperrten Start prüfen. Niemals eine laufende macOS-Programmdatei überschreiben. Bei einem Fehler die vorige geprüfte Version und eine getrennte Sicherung verwenden.

Die Anzeige „verschlüsselt“ beschreibt den gespeicherten Tresor. Sie ist kein Nachweis gegen Administratoren, einen kompromittierten Host oder eine bösartige Zielwebsite. Physische Passkeys, Herausgebersignierung, Notarisierung und native Windows-Kernel-Abnahme bleiben eigene Freigabeschritte.
